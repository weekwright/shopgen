what shopgen run does for each planned order

On resume

Settle the in-flight order

After a crash, kill -9 or a second Ctrl-C mid-request, state.json still names the in-flight index. shopgen looks it up by its sgseq tag before creating anything.

1 · before the request

Record intent

Wait for the pace slot (60s ÷ opm × 1.02), then save inflight = i to state.json.

2 · the request

orderCreate

Tagged sgseq-<run>-<i>, unique per planned order, with sourceIdentifier shopgen:<run>:<i>.

Created

Append to orders.jsonl; run orderCancel if the plan says cancelled (its own 2-minute timeout, so Ctrl-C can't skip it).

then done++, clear inflight, save state, next order

Ambiguous: it may have committed

Connection dropped after sending, HTTP 500 / 502 / 504, or an unreadable body. Never retried blindly. Wait 15s for search indexing, then query tag:'sgseq-<run>-<i>'.

found → treat as Created · not found → retry

Rate-limit userError

Message mentions limit, too many or throttl: wait 60s.

then retry, up to 6 attempts per order

Any other userError

Append to failures.jsonl as field.path: message and move on. If the first 3 attempts of a session all fail, stop and roll back so nothing is skipped.
